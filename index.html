Customer Churn MLOps Platform

A threshold chosen from retention economics rather than 0.5 was worth +19.7% campaign profit — on the same model.

An end-to-end system for telco churn: cross-validated model selection, isotonic calibration on a held-out split, MLflow tracking with a working model registry, a validated FastAPI service, a Docker image, and drift monitoring built from first principles.

  • ROC AUC0.844
  • PR AUC0.632
  • Profit uplift+$1,470

Logistic regression beat XGBoost in cross-validation, so that is what ships. The drift detector needed a Bonferroni correction — without it, 19 features produced roughly one false alarm on every clean window.

Python · scikit-learn · XGBoost · MLflow · FastAPI · Docker · GitHub Actions

Demand Forecasting

A forecasting method from 2000 beat gradient boosting — while fitting 590× faster.

Daily electricity demand over 1,440 days, evaluated across 25 rolling origins with eight models refitted at every one — rather than the single train/test split that makes a forecasting result mostly luck.

  • Rolling origins25
  • Best MASE0.738
  • Interval coverage96.1%

On a single holdout, SARIMA wins and seasonal naive comes last. Across 25 folds, Theta wins and seasonal naive is sixth of eight. The Gaussian prediction interval under-covers at 93.3%; split conformal holds 96.1%.

Python · statsmodels · scikit-learn · conformal prediction

Retail Analytics in SQL

The fourth-largest product by revenue sold nothing — 80,995 units ordered at 09:15, cancelled at 09:27.

Cohort retention, RFM segmentation, revenue concentration and basket affinity over 1,067,371 transaction lines, written as reviewable SQL on DuckDB rather than as pandas chains — plus a Streamlit dashboard reading the committed results.

  • Transaction lines1.07M
  • Top 10% of customers63.9%
  • Repeat rate72.4%

"Revenue" ranges over £3.4M depending on which exclusions apply — and not monotonically, since removing cancellations raises the total. Retention does not decay, which says this is a wholesale business, not consumer e-commerce.

SQL · DuckDB · Python · pandas · Streamlit

Semantic Search & RAG

The embedding model lost to BM25 — and ran 9× slower.

Retrieval measured against ground truth rather than demonstrated on three cherry-picked queries: 2,067 documents, 10,570 labelled questions, scored on Recall@k, MRR and nDCG over a 2,000-query sample.

  • Recall@1, reranked0.883
  • Hybrid miss rate4.1%
  • Queries evaluated2,000

Cross-encoder reranking was the largest single win — Recall@1 from 0.755 to 0.883 — at 175× the latency, which is the argument for two-stage retrieval rather than against reranking. BM25 is implemented from scratch so the ranking stays auditable.

About

I came to machine learning through economics and statistics, and the training is why this portfolio looks the way it does.

Econometrics is organised around one uncomfortable question — is this effect real, or is the data flattering you? — and it turns out to be the right question to carry into a model. It is the reason every project here reports an effect size and an interval rather than a bare p-value, tunes its thresholds on validation and touches the test set once, and writes down what the result does not support.

Around that, I work across the whole path a data problem takes: the SQL that shapes the raw table, the statistics that decide whether an effect is real, then the model, the service that serves it and the monitoring that tells you when it has stopped working.

The discipline keeps producing findings I did not expect — a keyword search beating a neural retriever, a forecasting method from 2000 beating gradient boosting, a bestselling product that turned out to have sold nothing at all. Those are in the write-ups too, because a portfolio that only contains wins is not evidence of judgement.
